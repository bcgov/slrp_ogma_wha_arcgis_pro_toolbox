# Check In Dataset

## What It Does

**Check In Dataset** automates the multi-step dataset check-in workflow for OGMA, LU, SLRP, and WHA submissions. It runs all check-in steps in sequence from a single ArcGIS Pro tool dialog, replacing the manual copy-and-check procedure.

The tool is **read-only on the source data throughout** — it never edits or locks the Returned FGDB. It copies data out; it never writes data back in.

---

## When to Use It

Use this tool after a dataset has been returned by the submitter and you are ready to:

1. Confirm all required files are present in the update directory.
2. Run Attribute QA/QC before accepting the submission.
3. Review the topology report.
4. Promote the Returned FGDB to `UpdateManagement\<Type>\CurrentUpdate`.
5. Place the QA and topology reports in the Update Emails folder for the request.

---

## Prerequisites

Before running the tool, the update directory must contain:

| File | Description |
|---|---|
| `<DatasetName>.gdb` | The Returned FGDB (exactly one `.gdb` per update directory) |
| `<name>_attribute_check_<date>.txt` | QA/QC report from a previous run (optional; a new one is generated by this tool) |
| Any `.csv` or `.txt` whose filename contains `top` (case-insensitive) | Topology error report — e.g. `topology_report.csv`, `TopologyReport.csv`, `topo_report.txt`. ArcGIS Pro topology exports are UTF-16 LE; other tools may use UTF-8, which is also accepted. |

The tool checks for all three and reports what is present or missing before proceeding. Missing files generate warnings but do not stop the tool (except a missing Returned FGDB, which aborts).

If more than one topology report candidate is found (multiple files matching the pattern), the tool picks the first match alphabetically and warns you.

The GDB name must contain one of these substrings for the tool to auto-detect the dataset type:

| GDB name contains | Type detected |
|---|---|
| `old_growth_management_area` | OGMA |
| `landscape_unit` | LU |
| `slrp_planning` | SLRP |
| `wildlife_habitat_area` | WHA |

## Parameters

| # | Parameter | Type | Description |
|---|---|---|---|
| 1 | **Update Work Area Directory Containing Returned FGDB** | Folder | The `UpdateWorkArea\<Type>` folder containing the Returned FGDB and report files. |
| 2 | **Input Feature Class (inside Returned FGDB)** | Feature Layer | The feature class inside the Returned FGDB to run QA against. Add it to the map first, or browse to it. |
| 3 | **Master Feature Class (for Attribute QA)** | Feature Layer | The master/replica feature class used as the reference for QA field and domain checking. |
| 4 | **Update Email Folder for This Request** | Folder | The existing `Update_Emails\<RequestFolder>` folder where QA and topology reports are copied. |
| 5 | **Destination CurrentUpdate Folder (where the Returned FGDB is copied)** | Folder | The `CurrentUpdate` folder that the Returned FGDB is copied into. Defaults to the production OGMA `CurrentUpdate` (from `.env` `CURRENT`). **Change this to the sandbox equivalent when doing a test run** — the tool writes only to the folder chosen here. |

## Workflow Steps

The tool runs 6 steps in order. A progress bar tracks each step.

### Step 1 — File Checklist
Scans the **Update Work Area Directory** and reports whether the Returned FGDB, QA/QC report(s), and `topology_report.csv` are present or missing. No files are modified.

### Step 2 — Derive Dataset Type
Reads the name of the Returned GDB and matches it to a dataset type (OGMA / LU / SLRP / WHA). **If no match is found, the tool aborts here.** The type is used to determine the correct destination path under `UpdateManagement`.

### Step 3 — Attribute QA/QC 
Runs the Attribute QA tool (`attribute_qa_v8`) against the Input Feature Class, comparing it to the Master Feature Class. Generates `.txt`, `.json`, and `.html` report files alongside the input dataset.

**If QA raises an error, the tool aborts and the copy steps do not run.** Fix the reported issues and re-run.

### Step 4 — Topology Report Display
Reads the topology report found by Step 1 and prints every row to the tool messages panel. **This step is informational only — the tool does not pass or fail based on topology errors.** The user determines whether the topology is acceptable.

The topology report is any `.csv` or `.txt` file in the update directory whose name contains `top` (case-insensitive). Examples that all match: `topology_report.csv`, `TopologyReport.csv`, `topo_report.txt`, `Top Report.csv`. ArcGIS Pro UTF-16 LE exports and UTF-8 exports are both supported.

### Step 5 — Rename Existing GDB(s) In Place, then Copy Returned FGDB

For every `.gdb` already present in the **Destination CurrentUpdate Folder** (parameter 5) that is not already flagged for deletion, the tool renames it in place by appending `_to_delete` to its name. For example:

```
old_growth_management_area_bc_2026_07_10.gdb
    -> old_growth_management_area_bc_2026_07_10_to_delete.gdb
```

The renamed GDB stays in the **same** CurrentUpdate folder — nothing is moved, deleted, or overwritten. The DRM is expected to review the flagged `*_to_delete.gdb` folders and remove them manually after confirming the new check-in is good.

After the renames succeed, the tool copies the entire Returned FGDB into the destination folder:

```
<Destination CurrentUpdate Folder>\<ReturnedGDBName>.gdb
```

Uses `arcpy.management.Copy()` with `arcpy.env.overwriteOutput` explicitly set to `False` for the duration of the copy, so any residual name collision raises loudly rather than silently replacing data. The source Returned FGDB is never modified.

**Abort conditions in Step 5:**
- A leftover `*_to_delete.gdb` from a prior check-in cycle already exists at the destination. Delete or move it manually and re-run.
- The rename fails because a GDB is locked (typically because the GDB or a feature class inside it is open in this ArcGIS Pro session or another application). Remove any layers from this GDB from the map, close other applications that have it open, and re-run.

In both cases the tool aborts before any copy — no data is destroyed.

After Step 5, the tool prints a summary block listing the full UNC path of every `*_to_delete.gdb` it just created so the DRM can navigate straight to them.

### Step 6 — Copy Reports to Update Emails Folder
Copies the following files directly into the **Update Email Folder**:

- `<name>_attribute_check_<date>.txt`
- `<name>_attribute_check_<date>.json`
- `<name>_attribute_check_<date>.html`
- `topology_report.csv`

Files that do not exist are skipped with a warning.

---

## Abort Conditions

The tool stops early and does not run the copy steps if:

- The update directory contains zero or more than one `.gdb`
- The GDB name does not match any known dataset type substring
- Attribute QA/QC raises an exception
- A `*_to_delete.gdb` leftover from a previous check-in already exists in the destination CurrentUpdate folder
- An existing GDB in the destination CurrentUpdate folder is locked and cannot be renamed

In all cases the tool message panel explains what went wrong and no source data is modified.

## Output Locations

| What | Where |
|---|---|
| Returned FGDB | The **Destination CurrentUpdate Folder** chosen in parameter 5 (defaults to `\\spatialfiles3.bcgov\slrp\UpdateManagement\OldGrowthManagementAreas\CurrentUpdate`) |
| Renamed incumbent GDB(s) | Same folder as above, with `_to_delete` appended (e.g. `<name>_to_delete.gdb`) — left in place for the DRM to remove manually |
| QA report (.txt / .json / .html) | The Update Email Folder you specified in parameter 4 |
| Topology report (.csv) | The Update Email Folder you specified in parameter 4 |

## Running Standalone (for testing)

`check_in_dataset.py` can be run outside ArcGIS Pro as a standalone script, either against sandbox data (no arguments) or with explicit paths.

**Testing mode** — loads all five paths from the `TEST_*` keys in `.env`, so runs always target the sandbox, never production:

```powershell
python script_modules\check_in_dataset.py
```

**Explicit mode** — five positional arguments:

```powershell
python script_modules\check_in_dataset.py <update_dir> <in_dataset> <master_dataset> <email_folder> <dest_current_dir>
```

The standalone runner still requires arcpy on the Python path and a populated `.env`.
